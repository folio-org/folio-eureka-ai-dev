## What is Lists

Lists is the FOLIO application for building, saving, refreshing, and exporting query-based record sets across many record types. It is powered by FQM (FOLIO Query Machine), which consolidates data from multiple modules for cross-application querying. Lists are persisted artifacts (not live views) and are commonly used as a selection step before bulk actions such as Bulk Edit.

## Key Terms

| Term | Definition |
|---|---|
| FQM | FOLIO Query Machine query engine used by Lists |
| List | Saved query definition plus a refreshable record set |
| Record type | Entity type queried by the list (Items, Users, Invoices, etc.) |
| Query Builder | UI modal used to define field/operator/value logic |
| Record set | Results produced during the latest refresh run |
| Canned list | Pre-built list available in Lists |

---

## Record Hierarchy / Architecture

- UI app (Lists)
- Query definition (field + operator + value, AND/OR)
- FQM engine execution
- Snapshot result set
- Actions on snapshot:
  - Refresh list
  - Export to CSV
  - Duplicate list
  - Edit list metadata/query

ASCII view:

Lists UI -> Query Builder -> FQM engine -> Snapshot record set -> (Refresh | Export | Duplicate | Edit)

---

## Lifecycle / Workflow

| Status | Description |
|---|---|
| Active | List is refreshable and can be updated from source data |
| Inactive | List is frozen and cannot be refreshed until reactivated |
| Deleted | List removed and no longer available |

Primary action flow:

Create/Save -> Refresh -> View/Filter/Export
                 |           |
                 -> Duplicate -> Edit -> Save
                 -> Delete (terminal)

## Common Verification Patterns

### Actions menu availability on list details

Action: Open an active list details page and click Actions.
Expected:
- Actions menu opens.
- Refresh list, Duplicate list, and Export options are visible.
- Option enablement reflects list status and permissions.

### Duplicate list prepopulation

Action: From list details, choose Actions -> Duplicate list.
Expected:
- Duplicate list page opens.
- List metadata/query fields are prepopulated from source list.
- Saving creates an independent copy (original list remains unchanged).

### Refresh recency evidence

Action: Trigger Refresh list on an Active list and open the updated list view.
Expected:
- Refresh completion toast appears.
- Last updated timestamp changes.
- Result set reflects refreshed snapshot state.

## Key Business Rules for Test Cases

1. List record sets are snapshots and require manual refresh to reflect current data. (cases)
2. Inactive lists cannot be refreshed until status is switched back to Active. (cases)
3. Duplicate list creates an independent copy and prepopulates fields/query from the source list. (cases)
4. Refresh updates list freshness indicators (including Last updated evidence). (cases)
5. Export operates on the latest refreshed snapshot, not on unrefreshed live data. (cases)
6. Actions menu options and outcomes are constrained by Lists capability sets. (cases)
7. Users without Lists app permissions cannot access Lists even if they hold unrelated entity permissions. (cases)
8. Query builder supports complex field/operator logic and must preserve query editability across edit/duplicate flows. (cases)
9. Non-queryable array fields may still be available for export/column selection in supported record types. (cases)
10. Multi-user concurrency must be handled for refresh/export/edit collisions with explicit error feedback. (cases)
