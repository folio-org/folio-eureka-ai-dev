## What is Agreements

The Agreements app is part of FOLIO's Electronic Resource Management (ERM) suite. It manages contracts with content vendors for electronic resources — defining what content the library can access, under what terms, for what period. An agreement record is the central hub connecting vendors (Organizations), licensing terms (Licenses app), acquisitions spend (Orders app POLs), e-resource content (internal Local KB or external eHoldings), usage statistics (eUsage), and notes. The app is built on `mod-agreements` (Grails/Groovy) and `ui-agreements` (React/Stripes). Current UI version: **12.1.x (Trillium / R1 2026)**.

## Key Terms

| Term | Definition |
|---|---|
| **Agreement** | A contract record describing content access rights with a vendor |
| **Agreement line** | A single e-resource entry (package or title) covered by the agreement |
| **E-resource** | An electronic resource — can be a Package, a Title (PCI), or Unlinked |
| **Internal KB** | FOLIO's own local knowledge base (managed via Local KB admin app) |
| **External KB / eHoldings** | Third-party KB (e.g. EBSCO) accessed via eHoldings integration |
| **GOKb** | Global Open Knowledgebase — external title/package registry for search integration (added Trillium) |
| **Package** | A collection of e-resource titles from a provider |
| **PCI** | Package Content Item — individual title within a package |
| **Basket** | Temporary holding area for selected e-resources before adding to an agreement |
| **Platform** | Delivery platform for e-resources; can have proxy and URL customization settings |
| **POL** | Purchase Order Line from the Orders app, linked to an agreement line |
| **Acquisition Unit** | Controls record-level access to agreements (view/edit/create/delete) |
| **Supplementary property** | Custom metadata field (text, integer, decimal, date, pick list) defined in Settings |
| **Supplementary document** | File attachment or URL associated with an agreement record |
| **Controlling license** | The primary license governing this agreement (only one allowed per agreement) |

## Record Hierarchy / Architecture

```
Agreement
├── Agreement periods (1+ required)
├── Agreement lines (0+)
│   ├── Linked to Internal KB package or title
│   ├── Linked to eHoldings resource (package or title)
│   ├── Unlinked (manual / description only)
│   ├── Linked PO lines (0+)
│   ├── Custom coverage (if e-resource linked)
│   └── Documents (0+)
├── License information
│   ├── Controlling license (0 or 1)
│   ├── Historical licenses (0+)
│   ├── Future licenses (0+)
│   └── Supplemental licenses (0+)
├── Organizations (0+, each with a role)
├── Internal contacts (0+, linked to Users app)
├── Supplementary properties (0+)
├── Supplementary documents (0+)
├── Related agreements (0+, each with a relationship type)
├── Usage data providers (0+, linked to eUsage)
├── Tags (0+)
├── Notes (0+)
└── Acquisition units (inherited / assigned)
```

## Common Verification Patterns

> Copy into expected results. These reflect how the team writes assertions for this area.

### 1. Create agreement line via eHoldings from Agreement record

```
Action:   Click "Actions" button in the "Agreement lines" accordion
          Select "New agreement line"
          Click "eHoldings" toggle
          Click "Link e-resource" button
          Search for a package in the "Select package" modal; select it
          Click "Save & close"

Expected: "Agreement line" details pane is displayed
          Toast message "Agreement line created" appears
          Selected package appears in the "Agreement lines" accordion
          with correct resource name populated
```

### 2. Create agreement from eHoldings Package view

```
Action:   Navigate to eHoldings package; open Package details
          Click "New" in the "Agreements" accordion
          Fill Name, Status, and Start date
          Click "Save & close"

Expected: "Agreement" details pane is displayed
          Toast message "Agreement created: {agreement name}" appears
          Package is displayed in the "Agreement lines" accordion
```

### 3. Delete agreement line

```
Action:   Open agreement line
          Click "Actions" button; select "Delete"
          Confirm in the "Delete agreement line" modal

Expected: Toast message "Agreement line deleted" appears
          Agreement line is removed from the "Agreement lines" accordion
```

### 4. Acquisition unit restricts edit (user NOT in unit)

```
Precondition: Agreement has an acquisition unit; user is not assigned to it.

Action:   Navigate to agreement; open Actions menu

Expected: "Edit" option is greyed out and inactive
          In "Agreement lines" accordion, "New agreement line" option is greyed out
          Opening an agreement line: Edit and Delete options are greyed out
```

### 5. Agreement blocked from deletion due to existing content

```
Action:   Open an agreement that has agreement lines
          Actions > Delete; confirm in dialog

Expected: Toast: "Agreement was not deleted because it has one or more agreement lines."
          Agreement record remains; user remains on the Agreement details pane
```

## Key Business Rules for Test Cases

1. **Name and Status are the only required agreement fields** — plus at least one period with a Start date. (cases + github)
2. **At least one period required** — agreement cannot be saved without an agreement period. (cases + github)
3. **Period dates must not overlap** — error: `"The following periods have overlapping dates: {fields}"`. (cases + github)
4. **Only one open-ended period allowed** — error: `"Cannot have multiple open-ended agreement periods."` (cases + github)
5. **Status = Closed triggers Reason for closure** — field is only visible when Status = Closed; switching away clears the reason with a warning. (cases + github)
6. **Agreement cannot be linked to itself** — error displayed immediately. (cases + github)
7. **Only one Controlling License allowed per agreement** — adding a second Controlling shows an error. (github)
8. **Agreement cannot be deleted if it has lines, licenses, or related agreements** — each shows a distinct blocking error toast. (cases + github)
9. **Agreement line requires either a linked e-resource OR a description** — cannot save with neither. (github)
10. **Multiple POLs can link to one agreement line** — no upper limit. (cases)
11. **Acquisition units restrict record-level access** — user not in the unit sees greyed-out Edit/Delete/New agreement line actions. (cases + jira)
12. **Agreement lines sort order: Name → Reference → UUID** — applied in UI MCL. (jira ERM-1931)
13. **Duplicate agreement feature** — creates "Copy of: {name}"; user can select which sections to copy; fails if name already exists. (cases + github)
14. **eHoldings resourceName auto-populates on line creation** — when linking an eHoldings resource, the resource name is populated in the agreement line. (cases + jira ERM-4007/4008, fixed Trillium)
15. **Package synchronisation can be toggled** — per-package from Package view, or multi-select in Local KB. (jira + github)
16. **Content type is multi-value** — "Add content type" without selecting a value blocks save; must fill or delete. (github)
17. **Alternative names: same rule as Content type** — "Add alternative name" without value blocks save. (github)
18. **File download requires a separate Capability Set** — `Procedural - UI-Agreements Agreements File - Execute` even if user has Edit. (cases + github)
19. **eUsage accordion requires separate eUsage permission** — not in standard Edit capability. (github)
20. **Status values are configurable** — never hard-code the list; check Settings → Agreements → Pick lists per environment. (github)
21. **Agreement export**: Actions → Export agreement (JSON); Actions → Export e-resources (JSON or KBART). Export starts with an info toast. (cases + github)
22. **Supplementary property cannot be Primary and Deprecated simultaneously** — validation error on save. (github)
23. **Supplementary property in use cannot be deleted** — specific error message shown. (github)
24. **Pick list value in use cannot be deleted** — specific error referencing the pick list and agreements. (github)
25. **Internal contact must be a FOLIO Users app record** — cannot add free-text names; linked via look-up. (cases + github)
26. **Agreement columns are configurable** — users can modify which columns appear in the Agreement lines MCL. (jira ERM-3133)
27. **Related agreement requires a relationship type** — cannot link without selecting it; types are configurable. (github)
28. **License and business terms accordion is conditional** — only shown when a Controlling license is linked. (github ERM-1578)
29. **Agreement start/end derived from periods** — earliest period start = agreement start date; latest period end = agreement end date. (github)
30. **"Hide internal KB" setting hides basket and E-resources tab** — controlled per-institution in Settings → Agreements → General. (github + cases)
31. **Keyboard shortcut Ctrl+Alt+E (open edit)** — previously caused Euro € to be typed; fixed in Trillium (ERM-4070). Use Cmd+S to save on macOS. (jira + github)
32. **GOKb search integration (Trillium+)** — adds GOKb as a third source for agreement lines in addition to Local KB and eHoldings. (github 12.1.0 changelog)
