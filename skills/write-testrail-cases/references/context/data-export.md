## What is Data Export

The Data Export app exports bibliographic, holdings, item, and authority data from FOLIO as MARC 21 (.mrc) files. Staff upload a .csv file of UUIDs or a .cql file containing a CQL query, select a job profile, confirm the record type, and the system generates a downloadable MARC file logged in the Logs pane. Exports can also be triggered from the Inventory and MARC Authority apps via the Actions menu (quick export), where the UUID .csv downloads immediately while the .mrc file is generated asynchronously and logged in Data Export.

---

## Key Terms

| Term | Definition |
|---|---|
| Job profile | Top-level export configuration that links a record type to a field mapping profile. Entry point for running an export. |
| Field mapping profile | Defines which FOLIO fields map to which MARC fields in the output, including transformations and field suppression. |
| Transformation | A mapping rule inside a field mapping profile that routes an Inventory/Holdings/Item field to a specific MARC field, indicators, and subfield. |
| Fields suppression | A setting in a field mapping profile that excludes specified MARC tags (three-digit codes, comma-separated) from the generated export output. |
| SRS | Source Record Storage — the FOLIO store holding the original MARC records. Instances with SRS records export their full underlying MARC; FOLIO-native instances get simplified generated MARC. |
| Quick export | Export triggered from Inventory (Actions → Export instances (MARC)) or MARC Authority (Actions → Export selected records (CSV/MARC)). UUID .csv is downloaded immediately; .mrc appears asynchronously in Data Export logs. |
| Running accordion | Accordion in the Jobs pane that shows in-progress export jobs with a progress bar. |
| View all | Button on the Logs pane that opens the full log history with search and filter capabilities (replaces the 25-record default view). |
| Purge window | Authority records set for deletion are accessible for 7 days; after that they are purged from SRS and cannot be exported by any profile. |

## Record Hierarchy / Architecture

```
Job Profile  (entry point — what to run)
  └── Field Mapping Profile  (what fields to include and how to transform)
        ├── FOLIO Record Types (checkbox selection — at least one required)
        │     ├── Source Record Storage (entire record)   [exports full SRS MARC]
        │     ├── Inventory instance (selected fields)    [generated on-the-fly]
        │     ├── Holdings                                [appended to MARC output]
        │     └── Item                                    [appended to MARC output]
        ├── Transformations  (MARC field/indicator/subfield mappings)
        └── Fields Suppression  (MARC tags to exclude; comma-separated 3-digit codes)
```

## Lifecycle / Workflow

### Export Job Lifecycle

| Phase | UI representation |
|---|---|
| File uploaded | Progress bar appears under "Running" accordion in Jobs pane |
| Processing | "Select job profile to run the export" pane displayed; job profile selection & record type confirmation |
| Running | Progress bar shows in "Running" accordion; "Triggered by {userName}" and "Job profile: {jobProfile}" shown |
| Completed | Row added to Logs table with Status = "Completed"; filename is a hyperlink |
| Completed with errors | Row added with Status = "Completed with errors"; filename is a hyperlink; click row to see per-record errors |
| Fail | Row added with Status = "Fail"; filename is NOT a hyperlink (non-clickable); click row to see error message |

### Export Job Statuses

| Status | Meaning |
|---|---|
| **Completed** | All records exported successfully; .mrc file downloadable |
| **Completed with errors** | Partial export; some records failed; .mrc file still downloadable; per-record error log available |
| **Fail** | No records exported; no .mrc file; click the row (not the filename) to see errors |

### Profile Lifecycle

| Action | Condition |
|---|---|
| Job profile — can edit/delete | Profile has never been used in an export |
| Job profile — cannot edit or delete | Profile has been used in at least one export; Edit and Delete actions are disabled |
| Job profile — can duplicate always | Duplication is always allowed regardless of use |
| Field mapping profile — can edit/delete | Not currently assigned to any job profile |
| Field mapping profile — cannot edit or delete | Assigned to at least one job profile |

## Main Sections / UI Structure

### Panes

- **Jobs** pane (left) — "Drag and drop" area with "or choose file" button; "Running" expanded accordion [confirmed]
- **Logs** pane (main) — table of 25 most recent export jobs; "View all" button [confirmed]
- **Search & filter** pane (left, View all only) — ID search, Errors in export, Started running, Ended running, Job profile, User accordions [confirmed]
- **Data export** pane (Settings) — lists "Job profiles" and "Field mapping profiles" [confirmed]

### Accordions

| Accordion | Location | Default state |
|---|---|---|
| Running | Jobs pane | Expanded |
| Errors in export | Search & filter (View all) | Expanded |
| Started running | Search & filter (View all) | Collapsed |
| Ended running | Search & filter (View all) | Collapsed |
| Job profile | Search & filter (View all) | Collapsed |
| User | Search & filter (View all) | Collapsed |

### Logs Table Columns (default and View all)

`File name` · `Status` · `Total` · `Exported` · `Failed` · `Job profile` · `Started running` · `Ended running` · `Run by` · `ID`

- Default sort: **Ended running** descending (most recent on top)
- All columns are sortable; all show "Up-down" icon except "Ended running" which shows "v" (active sort)
- Sorting is preserved across page reload (F5) and navigation away and back to the app
- Sorting is reset to default "Ended running" descending when navigating from "View all" back to the Data export landing page via the header button

### Key Navigation Paths

- `Data export` (header icon) — opens landing page with Jobs + Logs panes
- `Settings > Data export > Job profiles`
- `Settings > Data export > Field mapping profiles`
- `Inventory > [instance list] > Actions > Export instances (MARC)` — bulk quick export (multiple selected)
- `Inventory > [instance detail] > Actions > Export instance (MARC)` — single quick export
- `Inventory > [instance list] > Actions > Save instances UUIDs` — download UUID .csv for manual upload
- `Inventory > [instance list] > Actions > Save Instances CQL query` — download .cql file for manual upload
- `MARC authority > [authority list] > Actions > Export selected records (CSV/MARC)` — quick export
- `MARC authority > [authority list] > Actions > Save authorities CQL query` — download .cql file

## Common Verification Patterns

> Copy these into expected results. They reflect how the team actually writes assertions for this area.

### Pattern 1: Successful export with Edit capability

```
Action:   Navigate to Data export → click "or choose file" in Jobs pane → upload .csv file
          → "Select job profile to run the export" pane opens → click job profile
          → "Are you sure you want to run this job?" dialog → select record type from
          "UUIDs provided for this export" dropdown → click "Run"
Expected: Progress bar appears under "Running" accordion
          After job completes: new row in Logs table with:
            Status = "Completed"
            Job profile = "<selected job profile name>"
            Total = Exported (same value, no failures)
            File name is a hyperlink
          Clicking the filename hyperlink downloads the .mrc file
```

### Pattern 2: Export with duplicate SRS records (Completed with errors)

```
Action:   Run export for instances where at least one instance has multiple SRS records
Expected: Status = "Completed with errors"
          Failed column shows count: "{n} duplicate(s)"
          Clicking the row (not the filename) opens error log:
            ERROR Instance with HRID: {hrid} has following SRS records associated: {uuid1}, {uuid2},...
          Each affected instance has a separate error entry with UUID, HRID, Title, and link to record
          File name IS a hyperlink (partial export was generated)
```

### Pattern 3: View-only capability — export blocked

```
Action:   Log in with only Data - UI-Data-Export - View capability set
          → Navigate to Data export app
Expected: "Drag and drop" area in Jobs pane is disabled (cannot upload files)
          "Logs" pane is displayed with the table and "View all" button (enabled)
          Settings app is NOT available in the app menu
          Only "Data export" app is available
```

### Pattern 4: Quick export from Inventory (multi-record)

```
Action:   Inventory → select instance checkboxes → Actions → "Export instances (MARC)"
Expected: .csv file downloads immediately to local machine
          File name format: QuickInstanceExport_{YYYY-MM-DD}T{hh_mm_ss}+{hh_mm}.csv
          .csv contains UUIDs of selected instances without duplicates
          In Data export app: new row added to Logs with:
            Status = "Completed"
            Job profile = "Default instances export job profile"
            Run by = current user's username
          Clicking filename hyperlink downloads .mrc file
```

### Pattern 5: Sorting persistence across reload and navigation

```
Action:   On "View all" page, click a column header to sort (e.g., "ID" descending)
          → Reload page (F5)
Expected: Sorting preserved; "v" icon displayed next to "ID" column
          Records remain sorted by ID descending after reload

Action:   Click "Data export" header button while on "View all" page
Expected: Returns to landing page; default sort restored:
          "Ended running" descending; "v" icon next to "Ended running"
```

## Key Business Rules for Test Cases

1. **Job profile used in export → cannot be edited or deleted** — Edit and Delete actions are disabled; the only option is to duplicate the profile. (cases + jira)
2. **Field mapping profile assigned to a job profile → cannot be edited or deleted** — `Cannot delete mapping profile` modal shown with list of linked job profiles. Must unassign (or delete) the job profiles first. (cases + github)
3. **Field mapping profile requires at least one FOLIO record type checkbox** — saving without any type selected returns a validation error. (github)
4. **Output format is always MARC** — no other output format option exists. (github)
5. **Default authority export profile rejects records set for deletion** — each such record produces a separate per-record error in the log; export may still show "Completed with errors" if some records were valid. (existing context)
6. **Deleted authority export profile rejects non-deleted records** — same logic in reverse; wrong profile always results in per-record errors. (existing context)
7. **Records past the 7-day purge window → "Record not found"** — even the correct deleted profile cannot export purged records; individual error per record. (existing context)
8. **UUID must match the correct record type at confirmation** — staff must select the right type from "UUIDs provided for this export" dropdown; wrong type causes systematic failures. (cases)
9. **Quick export: UUID .csv is immediate; .mrc is async** — .csv arrives in browser immediately; .mrc appears only in Data Export logs. (cases)
10. **Logs show 25 most recent by default; "View all" shows complete history** — logs are never deleted; all history retained permanently; search and filter available only in View all. (cases)
11. **Fail status = no .mrc file generated** — file name in the log row is not a hyperlink; clicking the row itself opens error details. (cases)
12. **Completed with errors = partial .mrc file exists** — file is downloadable; per-record error details available by clicking the row. (cases)
13. **Subfields in transformations must begin with `$`** — e.g. `$a`, `$b`; omitting `$` triggers the `Please check your input` validation message. (github)
14. **FOLIO-native instances generate simplified MARC** — less complete than SRS MARC; note in expected results when the instance source is FOLIO vs MARC. (existing context)
15. **Large exports (>100,000 records) generate a .zip archive** — the .zip contains numbered .mrc slices; default slice size is 100,000; configurable via POST /data-export/configuration `{ "key": "slice_size", "value": "100000" }`. (cases)
16. **Multiple export jobs run simultaneously (async)** — small jobs are not queued behind large jobs; all run in parallel. (cases)
17. **Token for export file download never expires** — files from past export jobs remain downloadable indefinitely. (cases)
18. **Only .csv or .cql file extensions are accepted** — any other extension triggers the "Invalid file" modal. (cases + github)
19. **Sorting is preserved across page reload (F5)** — including with active filters on the View all page. (cases)
20. **"Job profile" filter (View all) shows only profiles used in at least one export** — unused profiles do not appear in the dropdown; API: `job-profiles?used=true`. (cases)
21. **"Errors in export" filter: Yes includes "Completed with errors" AND "Fail"; No includes only "Completed"** (cases)
22. **"Run by" column sort order differs by view** — View all page: FirstName, LastName; landing page: LastName, FirstName. (cases)
23. **No system-defined "Data Export" or "Data Export Admin" authorization roles exist** — must be created manually by assigning capability sets. (cases)
24. **Numeric values in logs table use thousands separators** — e.g. `1,000` records; relevant for Total, Exported, Failed columns when counts exceed 999. (cases)
