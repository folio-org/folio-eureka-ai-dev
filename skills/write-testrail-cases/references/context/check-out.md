## What is Check out

The Check out app allows library staff to lend items to patrons by scanning (or manually entering) patron cards and item barcodes. Staff select a service point, find the patron using a barcode, username, external system ID, or custom field, then scan item barcodes to create loans. The app applies circulation rules, enforces loan policies, patron blocks, and item limits, and handles proxy borrowing, multipiece items, check out notes, due date overrides, and patron-facing note pop-ups.

---

## Key Terms

| Term | Definition |
|---|---|
| Patron | Library user borrowing an item |
| Proxy | A patron acting on behalf of another patron (sponsor); the item is checked out to the sponsor |
| Sponsor | The patron on whose behalf a proxy acts |
| Circulation rule | A rule mapping combinations of patron group, material type, loan type, and effective location to a loan policy |
| Loan policy | Defines loan period, renewability, and closed-library due date management |
| Patron block | A manual or automated block preventing checkout; can be overridden with a comment |
| Item block | A block triggered by item limits in loan/material type rules; can be overridden |
| Check out note | A note attached to an item record that must be acknowledged before checkout proceeds |
| Multipiece item | An item where "Number of pieces" > 1; requires confirmation modal before checkout |
| Service point | Physical or virtual desk where checkout occurs; must be assigned to the staff user |
| DCB loan | Digital Cloud Borrowing loan; hides patron/staff info buttons in the action menu |
| Use at location | Hold shelf designation for items that patrons must use on-site |

```

└── Checkout Session

    │   ├── User expiration
    │   ├── Open loans (count)
    │   ├── Fees/fines owed (amount)
    │   ├── Open requests (count)
    │   └── Patron blocks (count)
    │
    └── Scanned Items (Scan items pane)
        └── Loan
            ├── No. / Barcode / Title / Loan policy / Due date / Time
            └── Actions: Loan details | Check out notes | Add patron info | Add staff info | Item details
```

## Lifecycle / Workflow

```
Staff opens Check out app
        │
        ▼
Scan patron card (barcode / username / external system ID / custom field / patron look-up)
        │
        ├─→ [Patron not found] → "User with this {identifier} does not exist" error
        ├─→ [Patron has no barcode] → "User does not have a barcode" error modal on item scan
        ├─→ [Patron has blocks] → "Patron blocked from borrowing" modal → Override or Close
        ├─→ [Patron has notes] → "Note for patron" modal → Close or Delete note (one at a time)
        └─→ [Proxy relationship] → "Who are you acting as?" modal → Self or Proxy for <sponsor>
                │
                ▼
        Scan item barcode
                │
                ├─→ [Item has check out note] → "Confirm check out" modal → Confirm or Cancel
                ├─→ [Multipiece item] → "Confirm multipiece check out" modal → Check out or Cancel
                ├─→ [Item status: Withdrawn/Missing/Lost and paid] → "Check out {status} item?" modal → Confirm or Close
                ├─→ [Item status: Checked out] → "Item not checked out" modal: "Item is already checked out"
                ├─→ [Item status: Declared lost / Claimed returned] → "Item not checked out" modal with status-specific message
                ├─→ [Non-loanable, no override permission] → Modal: item not loanable, Close only
                ├─→ [Non-loanable, with override permission] → Modal: item not loanable, Override + Close
                │       └─→ "Override loan policy" modal → date/time selector + required comment → Save & close
                └─→ [Success] → Item added to Scan items list with loan policy, due date, time
                        │
                        ▼
                End session (or scan next patron)
```

| Item Status | Checkout behaviour |
|---|---|
| Available | Checked out directly (or with modals) |
| Checked out | Blocked — "Item is already checked out" |
| Declared lost | Blocked — status-specific message |
| Claimed returned | Blocked — status-specific message |
| Withdrawn | Requires confirmation modal |
| Missing | Requires confirmation modal |
| Lost and paid | Requires confirmation modal |

## Main Sections / UI Structure

### Panes
- **"Scan patron card"** pane (left) — patron identifier input + borrower details [confirmed]
- **"Scan items"** pane (right) — item barcode input + list of checked-out items for the session [confirmed]

### Accordions
- No accordions in the main Check out app UI.
- Patron notes are managed via the **Notes** accordion in the Users app.

### Key Navigation Paths
- `Check out` — accessed directly from FOLIO app list
- `Settings > Circulation > Other settings` — configure patron identifier types, wildcard lookup
- `Settings > Circulation > Loans > Loan policies` — create/edit loan policies
- `Settings > Circulation > General > Circulation rules` — configure circulation rules
- `Settings > Calendar > All calendars` — configure service point calendars (affects due date)
- `Users > <user record> > Notes accordion` — assign notes that pop up at checkout
- `Check out > Scan items > Action menu (…) > Loan details` — opens loan details page

## Proxy Borrowing

A **proxy** is a patron who checks out items on behalf of another patron (the **sponsor**).

### Requirements
- The proxy relationship must be set up in the **Users app** on the sponsor's user record first.
- Cannot proxy for someone not configured in Users.

### Proxy checkout flow
1. Scan proxy patron's barcode.
2. **"Who are you acting as?"** dialog appears:
   - `{proxy} is acting as: Self` (radio button checked)
   - `Or acting as proxy for: {sponsor}` (radio button)
3. Select sponsor → click **Continue**.
4. Borrower section shows sponsor's details; Borrower's proxy section shows proxy's details.
5. Loan is recorded against the **sponsor's** account; proxy is noted.

### Inactive Proxy/Sponsor (Trillium)
- When proxy's expiration date is in the past: red warning **"Proxy user record expired"** displays in "Who are you acting as?" modal; the "acting as proxy for" radio is NOT clickable.
- When sponsor's expiration date is in the past: red warning **"Sponsor user record expired"** displays; radio button for sponsor is NOT clickable.
- ⚠️ This behaviour was partially DRAFT as of Trillium (STSMACOM-949) — verify in env.

## Check out Notes

- Notes assigned to an item in Inventory (Loan and availability accordion).
- At checkout, the `Confirm check out` modal appears; notes sorted most-recently-added first.
- Each note shows: date/time added, note text, user who added it (Lastname, Firstname).
- Clicking **Confirm** proceeds with checkout; clicking **Cancel** does not check out.
- After checkout, notes accessible via item action menu → `Check out notes`.

### End session
- Click **End session** button (bottom right) → clears patron and items; patron notes for next patron pop up after.

- Default: 3 minutes inactivity → session ends automatically. Configurable in Settings > Circulation > Auto-end session.

## Common Verification Patterns

> Copy these into expected results. They reflect how the team actually writes assertions for this area.

### Pattern 1: Successful checkout — item appears in Scan items list

```
Action:   Scan patron barcode → scan item barcode → no blocking modals.
Expected: Item row appears in Scan items pane: No. | Barcode | Title | Loan policy | Due date | Time | Action
          "Open loans" counter on Scan patron card pane is incremented by 1.
          "Total items scanned: N" label at bottom of Scan items pane is updated.
```

### Pattern 2: Due date cut-off by patron expiration

```
Action:   Loan period extends past patron expiration date.
Expected: "Due date" in Scan items list = patron's expiration date.
          "Time" = 11:59 PM.
          Flag icon displayed next to due date with tooltip "System calculated due date adjustment".
```

### Pattern 3: Override non-circulating item

```
Action:   Scan patron + item → item-not-loanable modal → click Override →
          fill required Comment field + set date/time → Save & close.
Expected: Modal closes. Item is checked out to patron.
          Due date = date/time set in Override modal.
          In Loan action table (Loan details page):
            Action = "Checked out through override"
            Action date = checkout date/time
            Due date = overridden date/time
            Source = "Lastname, Firstname Middlename" (linked to user profile)
            Comments = text entered in override modal
```

### Pattern 4: Multiple modals — ordering

```
Item has check out note AND is multipiece AND triggers non-loanable policy.
Order of modals:
  1. "Confirm check out" (check out note) → click Confirm
  2. "Confirm multipiece check out" → click Check out
  3. "Item not checked out" (non-loanable) → click Override or Close
```

### Pattern 5: Patron note pop-up sequence

```
Action:   Scan patron card for patron with 2 notes assigned to "Check out app".
Expected: "Note for patron" modal appears with most recently added note.
          Modal shows: note title, note text, date/time added, user who added it (Lastname, Firstname).
          Buttons: "Close" and "Delete note".
          After clicking Close: first modal closes; second modal appears with next note.
          After all notes dismissed: checkout proceeds normally.
```

### Pattern 6: Patron block override

```
Action:   Scan patron with manual block → "Patron blocked from borrowing" modal
          → click Override → enter comment → Save & close.
Expected: Patron block overridden. Comment saved on loan record.
          If patron has > 3 blocks: only 3 shown + "View block details to see additional reasons for block..."
```

### Pattern 7: Circulation rule verification via Loan details

```
Action:   Check out item matching specific material type circulation rule.
Expected: "Loan details" page shows correct Loan policy, Overdue fine policy, Lost item fee policy
          matching the applicable circulation rule (not fallback).
Action:   Check out item with no matching rule.
Expected: Loan policy matches the fallback rule.
```

## Key Business Rules for Test Cases

> Confirmed by ≥ 3 test case titles, acceptance criteria from Jira, or bug fix story. Source tagged.

1. An active patron with a barcode can be found by barcode, username, external system ID, or configured custom field; the scanner field label changes to match the configured identifier type. (cases + jira)
2. A patron without a barcode cannot have items checked out; "Item not checked out" modal shows `User does not have a barcode. A user barcode is required to check out an item.` (cases + jira: UICHKOUT-737)
3. Item barcodes must NOT be trimmed; leading/trailing spaces are preserved and the correct check out note modal appears for the untrimmed barcode. (cases + jira: UICHKOUT-903, UICHKOUT-506)
4. Items with statuses Declared lost or Claimed returned cannot be checked out regardless of permissions; only Close is offered in the error modal. (cases)
5. Items with statuses Withdrawn, Missing, or Lost and paid require confirmation modal; modal wording includes exact item status and whether suppressed from discovery. (cases + jira: UICHKOUT-605)
6. Multipiece items require the "Confirm multipiece check out" modal; Cancel does not check out; X button and Cancel both dismiss; default keyboard focus is on Check out button. (cases + jira: UICHKOUT-982)
7. Items with check out notes display the "Confirm check out" modal before checkout; notes are sorted most-recently-added first; each note shows date/time, text, adder name (Lastname, Firstname). (cases)
8. When an item has check out note + is multipiece + is non-loanable, the modals appear in order: check out note → multipiece → item not loanable. (cases)
9. Non-loanable items with override capability show Override + Close in the error modal; without override capability, only Close is shown. (cases + jira: UICHKOUT-784466 DRAFT)
10. Override loan policy modal requires Comment (mandatory) and date/time selector (default 11:59 PM); Save & close inactive until comment filled. (cases)
11. Due date is cut off at patron's expiration date (time = 11:59 PM) when loan period extends past expiration; flag icon + tooltip "System calculated due date adjustment" appears. (cases + jira: CIRC-886)
12. Patron blocks display "Patron blocked from borrowing" modal with reason, Override, Close, View block details; if > 3 blocks only 3 shown. (cases)
13. Patron blocks re-display when another item barcode is entered without first overriding; blocks cannot be bypassed. (cases)
14. Proxy workflow: scanning proxy barcode shows "Who are you acting as?" modal; item is checked out to the sponsor; loan details reflect sponsor. (cases + jira: UICHKOUT-433)
15. When proxy's or sponsor's expiration date is in the past, a warning displays and the proxy-for radio button is not clickable. (cases: 1263905 — DRAFT/partial)
16. When patron look-up returns multiple users with same field value, selecting a user fires query by `id ==` to ensure correct user loads. (cases + jira: UICHKOUT-991)
17. Circulation rules: most-specific matching policy applies; no-match falls back to fallback rule; loan details show correct policy names. (cases)
18. "Open loans" counter increments after each successful checkout in the session. (jira: UICHKOUT-959)
19. Patron notes assigned to "Check out app" pop up one at a time (most recent first) when patron card scanned; Close or Delete note; next note shown after each. (cases)
20. Select item modal (wildcard lookup): pagination 100 per page; Previous disabled on page 1, Next disabled on last page; dash for missing call number. (cases + jira: UICHKOUT-914, UICHKOUT-945)
21. Items held on the use-at-location hold shelf can be checked out; awaiting-pickup modal shows both pickup count and held-for-use-at-location count. (jira: UICHKOUT-962, UICHKOUT-965)
22. User custom fields displayed in borrower panel; render `—` when no value. (jira: UICHKOUT-989, UICHKOUT-996)
23. Print screen (Ctrl+P) generates print-friendly layout with borrower details (plus proxy if applicable) and one section per checked-out item; downloadable as PDF. (cases: 1030828)
24. Logging out while End session button is active does not produce errors; no errors on login page after 20-minute idle. (cases: 418580)
25. At 200% browser zoom with a long instance title, columns in Scan items pane do not overlap. (cases: 476742)
