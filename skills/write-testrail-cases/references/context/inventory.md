## What is Inventory

Inventory is the FOLIO application for managing bibliographic and item-level records. It stores Instances (bibliographic records), Holdings records, and Item records in a three-tier hierarchy. Staff use Inventory to create, search, browse, and manage all physical and electronic library holdings. Inventory integrates with Circulation (loans, requests), Data Import (MARC ingest), quickMARC (MARC editing), MARC Authority (authority linking), and Acquisitions (purchase orders, receiving).

## Key Terms

| Term | Definition |
|---|---|
| Instance | Bibliographic record describing a work (title, contributors, identifiers, publication data) |
| Holdings record | Links an Instance to a library location; holds call number and acquisition data |
| Item | Physical or digital copy attached to a Holdings record; carries barcode and status |
| HRID | Human Readable ID — system-generated, user-visible alternative to UUID |
| Source | Origin of a record: FOLIO (locally created), MARC (imported), or LINKED_DATA |
| MARC Instance | Instance whose Source is MARC; must be edited via quickMARC, not the standard form |
| Effective Call Number | Item's displayed call number — resolved from Item → Holdings → Instance in priority order |
| Bound-with | One physical Item associated with Holdings from multiple Instances |
| Fast Add | Simplified item-creation form for quick check-out scenarios |
| Call Number Browse | Browse interface for the entire catalog ordered by call number string |
| Subject Browse | Browse interface for subject headings |
| Contributors Browse | Browse interface for contributor (author) names |
| Instance classification browse | Browse interface for Dewey/LC classification values |
| Version History | Audit log of create/edit events per Instance, Holdings, or Item |
| Set record for deletion | Marks an Instance as a deletion candidate; does not delete automatically |
| Optimistic locking | Conflict detection when two users edit the same record simultaneously |
| Single Record Import | Imports a single bib record from an external Z39.50/SRU source |
| Suppress from discovery | Flag (per Instance/Holdings/Item) to hide from public discovery interfaces |
| Statistical code | Configurable code attached to records for statistical reporting |

## Record Hierarchy / Architecture

```
Instance  (bibliographic — one per work/edition)
  └── Holdings record  (one per location/library)
        └── Item        (one per physical/digital copy)
```

- One Instance → many Holdings (one per branch/location).
- One Holdings → many Items (multiple copies).
- Bound-with: one Item → multiple Holdings (across multiple Instances).
- MARC Holdings (MFHD) is a separate record type for libraries using MARC-format holdings.

## Lifecycle / Workflow

### Item Status Transitions

| Status | Set by |
|---|---|
| Available | Check-in / initial creation |
| Checked out | Check-out event |
| In transit | In-transit check-in (item travelling between service points) |
| Awaiting pickup | Hold fulfilled, item at pickup location |
| Awaiting delivery | Delivery request fulfilled |
| In process | Staff action (acquisitions/cataloging) |
| In process (non-requestable) | Staff action |
| On order | Created via Receiving (before receipt) |
| Paged | Page request triggered |
| Declared lost | Staff action or patron claim |
| Aged to lost | Automatic (loan overdue policy) |
| Claimed returned | Staff action after patron claim |
| Lost and paid | Fine paid |
| Withdrawn | Staff mark-as-withdrawn action |
| Missing | Staff mark-as-missing action |
| Restricted | Staff restriction action |
| Order closed | Order closed without receipt |
| Long missing | Time-based automatic transition from Missing |
| Intellectual item | Placeholder; no physical counterpart |

### Instance / Holdings — no status field; lifecycle managed by staff actions

## Common Verification Patterns

### Instance creation verification

```
Action:   Fill Title field + Source = FOLIO → Save & close
Expected: New Instance detail pane opens.
          HRID is auto-generated and shown in Administrative data.
          Source = FOLIO.
          Toast: "Instance has been successfully saved"
```

### Item status change — mark as missing

```
Action:   Item detail pane → Actions → Mark as missing
Expected: Item Status field = "Missing"
          Toast: "Item {barcode} has been successfully marked as missing"
          Item detail pane refreshes without full page reload
```

### Holdings move to another Instance

```
Action:   Instance A → Holdings accordion → Actions → Move to another instance → select Instance B
Expected: Holdings disappears from Instance A's Holdings accordion
          Holdings appears under Instance B detail pane
          Items under moved Holdings appear under Instance B
          Toast: "Holdings has been successfully moved"
```

### Call Number Browse — anchor and pagination

```
Action:   Inventory > Call Number Browse tab → enter a call number prefix → click Search
Expected: Results anchored at entered call number.
          Rows above and below the anchor are visible.
          Clicking a result row opens the Instance detail pane.
          "Missing" items in the browse sequence are visible but flagged.
```

### Optimistic locking conflict

```
Action:   Open the same Instance record in two sessions.
          Session A edits and saves.
          Session B attempts to save.
Expected: Session B receives: "This record has been changed since you started editing.
          To save it, reload the record and make your changes again."
          Session B cannot overwrite Session A's changes.
```

## ECS / Multi-Tenant Notes

ECS-specific test cases exist for: Instance (section 27193), Holdings (37958), Item (37959, 37962, 38037, 74668), Search (26618, filters 37961, index management 90236), all Browse types, and most Settings sub-areas.

Key ECS patterns:
- **Shared instances** are visible across all tenants in a consortium; tenant-specific Holdings remain isolated to their tenant.
- **Held by facet** defaults to the current tenant context (UIIN-2820, Trillium).
- **Affiliation switching** is required to view or manage Holdings/Items in a different member tenant from Central.
- **Settings > Inventory** configuration scoped to Central tenant can be shared consortium-wide for call number type, classification type, etc.
- Central tenant administrators can manage Instance-level shared data; member tenants manage their own Holdings/Items independently.

## Key Business Rules for Test Cases

> Each rule confirmed by ≥ 3 case titles, an acceptance criterion, or a Jira story/bug. Source in parentheses.


1. User can create a FOLIO Instance by providing a Title and selecting Source = FOLIO; HRID is auto-generated on save (cases)
2. User can add Holdings to an Instance via 'Add holdings'; Holdings requires a permanent location (cases)
3. User can add an Item to a Holdings record; Item requires a Material type and Permanent loan type (cases)
4. Instance, Holdings, and Item each have an independent 'Suppress from discovery' flag; suppression at any level hides the record from patron-facing discovery (cases)
5. Item Status is set automatically by circulation events (check out, check in, in transit, paged) and cannot be manually set to those values (cases)
6. Effective Call Number on an Item resolves from Item-level first, then Holdings, then Instance in that priority order (cases)
7. User can move an Item from one Holdings to another Holdings within the same or a different Instance (cases)
8. User can move a Holdings record from one Instance to another Instance; all Items under the Holdings move with it (cases)
9. A MARC-sourced Instance cannot be edited via the standard Instance editor — staff must use quickMARC or Data Import (cases)
10. Optimistic locking prevents a user from overwriting changes made by another user since the record was last loaded; the second user sees a conflict error and must reload (cases)
11. User can browse the entire catalog by Call Number, Subject, Contributor, or Classification; browse results anchor at the entered term (cases)
12. Single Record Import allows importing one bib record from an external Z39.50/SRU source directly into Inventory (cases)
13. Bound-with links one physical Item to Holdings from multiple Instances; the Item appears in all linked Instance detail panes (cases)
14. Version History shows all create/edit events for an Instance, Holdings, or Item with timestamp, user, and changed field details (cases)
15. 'Set record for deletion' marks an Instance with a deletion flag; the physical deletion must be confirmed separately by staff (cases)
16. An Item cannot be deleted while it has an active loan; it cannot be deleted while it has an open request (cases)
17. Statistical codes can be attached to Instance, Holdings, and Item records and are managed in Settings > Inventory > Statistical codes (cases)
18. Advanced search in Inventory supports multi-field queries with AND/OR operators; results can be filtered by Holdings and Item fields as facets (cases)
19. User without the 'create instance' capability does not see the New button in Inventory (cases)
20. Tenant can configure default display columns for the Inventory results list (UIIN-3422, Trillium) (jira)
21. In ECS, the 'Held by' facet defaults to the current tenant context to filter results by local holdings (UIIN-2820, Trillium) (jira + cases)
22. Shared Instances are visible across all consortium tenants; Holdings and Items remain isolated per tenant (ECS) (cases)
23. Classification Browse shows a title count per classification heading (UIIN-3367, Trillium) (jira)
24. Bound-with action button on an Item is disabled while the Item record is unsaved (UIIN-3631, Trillium) (jira)
25. Instance detail pane may exhibit performance degradation when an Instance has very large numbers of Holdings — known boundary (UIIN-3660) (jira)
26. Item status values displayed in the Actions menu must use translated (localized) strings, not raw system keys (UIIN-3666) (jira)
27. Tags applied to Instance, Holdings, or Item records are searchable via the Tags facet in Search & filter (cases)
