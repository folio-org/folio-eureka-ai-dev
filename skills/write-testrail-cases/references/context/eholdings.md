## What is eHoldings

The eHoldings app manages the library's electronic resource holdings via an external knowledge base (KB). It connects to EBSCO's HoldingsIQ API — currently the **only supported external KB**. Changes made in FOLIO eHoldings or EBSCO Holdings Management are **immediately reflected** in both interfaces (real-time sync via API).

eHoldings allows libraries to:
- Browse and search providers, packages, and titles from the EBSCO KB
- Select/deselect packages and titles for the library's holdings
- Edit coverage settings, proxy settings, and custom labels
- Create custom packages and titles
- Link e-resources to Agreements in the Agreements app
- View usage & analysis (cost-per-use) data exported via Export Manager

## Key Terms

| Term | Definition |
|---|---|
| Provider | Content vendor (e.g. Elsevier, Wiley) — sourced from EBSCO KB; not editable |
| Package | Collection of titles from a provider; can be KB or custom |
| Title | Individual e-resource (journal, e-book, etc.) |
| Resource | A title in the context of a specific package (title + package combination) |
| KB | Knowledge base — EBSCO HoldingsIQ; the only supported external KB |
| Custom package | Library-created package (not from KB); can be deleted |
| Custom title | Library-created title linked to a custom package; can be deleted |
| Holdings status | Whether the library has selected (added) a package or title |
| Access status type | Library-defined label for a title's local access status |
| Usage Consolidation | SUSHI-based cost-per-use analytics feature requiring separate configuration |

## Record Hierarchy / Architecture

```
Provider (content vendor, e.g. Elsevier, Springer)
  └── Package (collection of titles, e.g. "Elsevier Freedom Collection")
        └── Title (individual e-resource, e.g. a journal or e-book)
              └── Resource (title in context of a specific package = title + package combination)
```

All Provider, Package, and Title KB data lives in EBSCO's knowledge base — FOLIO accesses it via HoldingsIQ API. Only library-local data (selection state, coverage, proxy overrides, custom labels, tags, notes) is stored in FOLIO.

## Lifecycle / Workflow

### Package / Title Holdings Status

| Status | Description |
|---|---|
| **Not Selected** | Exists in KB but not in library's holdings (default for KB content) |
| **Selected** | Library has added this package/title to their holdings |
| **{ N } of { M } titles selected** | Package is partially selected (some titles added) |

Status transitions require `Procedural - UI-Eholdings Package-Title Select-Unselect - Execute`.

### Package Visibility (Show to Patrons)

| Setting | Description |
|---|---|
| **Show to patrons** | Package/title is visible in discovery |
| **Not shown to patrons** | Hidden from patron-facing discovery interfaces |

## Export Feature

- **Package export**: Actions → `Export package (CSV)` — opens `Export settings` modal
- **Resource export**: Actions → `Export title package (CSV)` — opens `Export settings` modal
- **Export limit**: Maximum 10,000 titles per package export (UIEH-1336); "Export" button disabled when limit exceeded
- **Export fields (package)**: Package Name, Provider Name, Package Type, Content Type, Holdings status, Custom Coverage, Show To Patrons, Proxy, Access Status Type, Tags, Notes, Package/Provider Level Token
- **Export fields (title)**: Title name, Holding status, Coverage statement, Custom/Managed coverage dates, Proxied URL (Sunflower+), Custom labels, Access status type, Tags, Notes
- **Export processing**: Asynchronous via Export Manager; toast confirms job start with Job ID
- **UC Export**: `Export titles` action under Usage & analysis accordion (up to 200,000 titles)

## Usage & Analysis (Cost-Per-Use)

Requires:
1. `Data - UI-Eholdings Costperuse - View` capability
2. Usage Consolidation configured in Settings (SUSHI credentials + Usage Consolidation ID + client ID)

View options per package/resource:
- **Summary table** — cost, usage, % of usage, coverage
- **List of titles** — per-title breakdown with cost, usage columns
- **Export titles** — up to 200,000 titles; toast on start; CSV downloaded from Export Manager

Locale-based number/date formatting applied to exported files (Umbrellaleaf).

## Key Business Rules for Test Cases

> Every rule tagged with source: (cases) = confirmed by ≥3 case titles/steps; (github) = from source code/translations; (jira) = from story/bug descriptions.

1. **EBSCO is the only supported external KB** — without valid KB credentials in Settings, eHoldings shows no data (cases + github)
2. **Changes are real-time** — selecting/deselecting a package in FOLIO immediately reflects in EBSCO Holdings Management; proxy/token updates may take a few minutes (cases + github toast)
3. **Cannot delete KB packages or titles** — only custom packages/titles created locally in FOLIO can be deleted; KB content is read-only for deletion (cases + jira)
4. **Select/unselect requires a dedicated capability** — `Data - UI-Eholdings Records - Edit` alone does NOT allow adding/removing holdings; the `Procedural - UI-Eholdings Package-Title Select-Unselect - Execute` capability is also required (cases x8)
5. **Custom packages require Name + Content type** — these are the only required fields at creation (cases + github)
6. **Custom titles must be linked to a package** — field `Package *` is required; standalone titles cannot exist (github - `title.package.isRequired`)
7. **Proxy hierarchy: Resource > Package > Provider** — the most specific proxy setting wins; changing root proxy overrides all inherited proxies (cases + github warning message)
8. **Coverage set at package and resource levels** — resource-level coverage overrides package-level for that specific title; multiple date ranges allowed (cases x12+)
9. **Custom labels: up to 4, configured in Settings** — values are per Resource, labels apply across all title records institution-wide (cases + github)
10. **Usage & analysis requires two conditions** — the `Data - UI-Eholdings Costperuse - View` capability AND Usage Consolidation configured in Settings with valid SUSHI credentials (cases x5)
11. **Agreement linking is bidirectional** — linking a package/title in eHoldings creates an Agreement Line in the Agreements app; visible in both places (cases + github)
12. **Tags can be removed from records but not deleted from the system** — removing a tag only unlinks it; the tag remains available for selection (cases)
13. **Filter by Tag is hidden when user lacks tag permissions** — not shown rather than shown disabled (cases + UIEH-1313)
14. **Search defaults to Relevance sort** — alphabetical sort must be explicitly selected (cases)
15. **Selection status filter defaults to "All"** — both selected and unselected are shown by default (cases)
16. **Multiple packages per title** — the same title can appear in multiple packages; each is a separate Resource with independent selection/configuration (cases)
17. **Provider records not editable beyond proxy/tags/notes** — names, package lists, title data come from EBSCO KB and cannot be changed in FOLIO (cases + github)
18. **Export goes through Export Manager (async)** — triggered from Actions menu; files downloaded from Export Manager app, not directly; max 10k titles per package export (cases x10+ + UIEH-1336)
19. **"Export" button disabled when no fields selected** — user must select at least one field in the Export settings modal (cases x2)
20. **A user already assigned to one KB cannot be assigned to another KB** — modal "Already assigned to a knowledge base" is shown (cases x1)
21. **Assigned users are sorted by Last name alphabetically** — in the Assigned Users list at Settings (cases)
22. **Deleting an Access status type removes it from all assigned records** — confirmation modal shows count of affected records (jira UIEH story)
23. **Hidden title visibility indicated in Titles list (Umbrellaleaf+)** — "Hidden" shown in status column of Package title list MCL (github UIEH-1464)
24. **Packages facet on Titles search opens a "Filter packages" modal** (Ramsons+) — selection persists as facet filter; cancel clears facet (cases + UIEH-1350)
25. **Agreements accordion "New" button opens new Agreement in new tab** (Trillium+) — prevents losing eHoldings navigation context (jira UIEH-1446)
