# FOLIO environments for lookups

Use a live environment for Step 2/3 lookups: real ids, the GET that proves an `app-bug`, a setting's current value.
Environments are defined in the user config (`python -I "<SKILL_DIR>/scripts/config.py" show`); the snapshot
environments below are there by default, with empty admin credentials that are asked once and then reused.

## The nightly run's own environment is gone

`runNightlyCypressEurekaTests` runs against its own `cypress` environment (e.g. `https://folio-etesting-cypress-diku.ci.folio.org`,
API `https://folio-etesting-cypress-kong.ci.folio.org`, tenant `diku`). It exists only during nightly runs
(its DNS name does not resolve afterwards), so it cannot be queried. To confirm which host a build used:

```
curl -s "<jenkins build url>/consoleText"
```

and look for `https://...kong...ci.folio.org` / `...diku...` hosts in the output (search it rather than reading it whole).

Use the snapshot environments instead. Snapshot is a clone of the `cypress` environment and is normally updated
at almost the same time, so module versions and behavior match. It is still a different instance:

- Module behavior (validation, 4xx/5xx, response shape) and reference data loaded from sample data with fixed ids: a lookup is good evidence.
- Data created at runtime (records, ids generated by tests, settings changed by tests): values differ per environment. Keep `<placeholder>` in the data request, so the fix stays Needs verification.
- Say in `evidence` that the lookup was made on snapshot, not on the nightly environment.

## Default environments

| config name | UI | API | login tenant | use for |
|---|---|---|---|---|
| `snapshot` | `https://folio-etesting-snapshot-diku.ci.folio.org` | `https://folio-etesting-snapshot-kong.ci.folio.org` | `diku` | regular (non-ECS) tests |
| `snapshot-ecs` | `https://folio-etesting-snapshot-consortium.ci.folio.org` | `https://ecs-folio-etesting-snapshot-kong.ci.folio.org` | `consortium` (central) | tests tagged `...ECS` (`smokeECS`, `criticalPathECS`, `extendedPathECS`, `edgeCasesECS`) |

Both are Eureka platforms. The ECS member tenants are `college` and `university` (see `cypress/support/dictionary/affiliations.js` in stripes-testing).

## Querying

```
python -I "<SKILL_DIR>/scripts/env_get.py" snapshot "loan-types?limit=100"
python -I "<SKILL_DIR>/scripts/env_get.py" snapshot-ecs "locations?query=name==\"DCB\"" --tenant college
```

`env_get.py` logs in as the environment's admin (`POST /authn/login`), sends the GET with the token and prints
the status and body. For an ECS member tenant it logs in to the central tenant and sends the request with
`--tenant college` (or `university`). Exit code 3 means the admin username/password are not configured yet:
ask the user, save them (`config.py set environments.<name>.username ...` / `.password ...`) and rerun.

Another environment the user mentions (a bugfest, a team env): save it with
`config.py add-env <name> --api <url> --tenant <tenant> [--ui <url>] [--members a,b]` and query it by name,
or pass `--api --login-tenant --username --password` to `env_get.py` for a one-off request.

## Rules

- **GET only.** `env_get.py` sends nothing else (besides the login). Never send POST, PUT, PATCH or DELETE to these
  environments by other means: they are shared, and other people's tests run on them. Data fixes are written into
  the report for a person to apply.
- Never print tokens or passwords in replies or in the report.
