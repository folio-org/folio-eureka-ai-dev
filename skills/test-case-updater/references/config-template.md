# TestRail Config Template

Use this file as the shape for a new module config. Copy the block below into `references/config-<module>.md` and fill in the section IDs.

**One canonical path:** `references/config-<module>.md`, kebab-case — e.g. `references/config-lists.md`, `references/config-data-export.md`. No subdirectory, no other naming.

After creating a config, add a row for it to the Module Configs table in [../SKILL.md](../SKILL.md) so the skill can find it.

---

Everything between the outer fence is the file content to copy.

## Finding the values

**Section IDs** — open the section in TestRail and read the ID from the URL: `?/cases/view/14&section_id=XXXXX`. The number after `section_id=` is what you need. Collect every section the module owns; a phrase can appear in any of them.

**Target (archive) section** — the section pre-release cases are copied to before their originals are edited. `65470` is the usual FOLIO manual-tests archive, but confirm it for the project rather than assuming.

**Release threshold** — the `custom_release` option ID that divides pre-release from current. Cases below it get archived before being updated; cases at or above it are updated in place. Current FOLIO default is `20` (R1 2026 Trillium), meaning Sunflower and older are archived.

**Release option IDs** — verified on `foliotest.testrail.io`, project `14`:

| ID | Release |
|---|---|
| `21` | R2 2026 Umbrellaleaf |
| `20` | R1 2026 Trillium |
| `19` | R1 2025 Sunflower |
| `18` | R2 2024 Ramsons |
| `17` | R1 2024 Quesnelia |
| `16` | R2 2023 Poppy |

Descends to `1` (Q1 2019). ⚠️ These are option IDs, not labels, and they change as releases are added — confirm with `GET /index.php?/api/v2/get_case_fields` before relying on them.

---

## Notes

- A case whose `custom_release` is `null` belongs to neither bucket. The skill surfaces these and asks rather than guessing — no config value can resolve it.
- Keep source sections complete. A missing section means a silent partial run, which reads as success.
